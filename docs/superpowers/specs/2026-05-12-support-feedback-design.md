# 支持与反馈页设计

**日期：** 2026-05-12

## 目标

在现有设置层级结构下，将“支持与反馈”从通用占位页升级为真实二级页，首批支持以下能力：

1. 展示联系邮箱 `reedllll.163.com`
2. 点击邮箱后复制到系统剪贴板
3. 提供“应用评分”入口，但当前仅保留占位反馈
4. 提供“分享 App”入口，并明确未来支持微信 / QQ 分享，但当前仅保留占位反馈

本次不改动“关于”页面，不实现真实评分跳转，也不实现真实分享逻辑。

## 背景

当前设置模块已经完成首页与二级页容器结构：

- `SettingsContainerFragment` 负责设置模块内的子页面切换
- `SettingsHomeFragment` 负责展示设置首页入口
- `SettingsSection.SUPPORT` 当前仍指向 `SettingsPlaceholderFragment`
- `SettingsSection.ABOUT` 同样指向 `SettingsPlaceholderFragment`

这意味着“支持与反馈”当前只有入口，没有真实业务页面。现有设置模块已经有稳定的二级页视觉结构和导航回退逻辑，因此本次设计应优先复用现有设置架构，而不是引入新的导航方式或弹窗形态。

## 方案选择

本次采用独立真实二级页方案：

- 新增 `SupportFeedbackFragment`
- 新增对应布局 `fragment_support_feedback.xml`
- 将 `SettingsSection.SUPPORT` 的路由从通用占位页切换为真实页面
- `SettingsSection.ABOUT` 继续保持原有占位页行为

不采用以下方案：

- 不复用 `SettingsPlaceholderFragment` 承载真实业务内容，避免占位页被污染为混合页面
- 不改为弹窗、底部弹层或系统对话框，保持设置模块“首页 -> 二级页”的结构一致性
- 不为当前页面引入单独 `ViewModel`，因为本次不存在持久化、异步请求或复杂状态管理需求

## 用户可见结构

### 设置首页入口

设置首页中的“支持与反馈”条目继续保留原有位置与文案，点击后进入新的真实二级页。

“关于”条目保持原样，仍然进入原占位页。

### 支持与反馈二级页

页面整体风格与现有设置二级页保持一致，包含：

- 顶部返回按钮
- 页面标题
- 页面说明文案
- 3 个列表式操作项

页面操作项顺序固定为：

1. 联系邮箱
2. 应用评分
3. 分享 App

## 交互定义

### 联系邮箱

- 展示值固定为 `reedllll.163.com`
- 点击整个条目后，将该文本复制到系统剪贴板
- 复制成功后显示短提示，例如“邮箱已复制”

本次按需求原样展示该字符串，不对其邮箱格式进行修正或推断。

### 应用评分

- 展示为可点击操作项
- 点击后仅显示占位提示，例如“应用评分功能暂未开放”
- 本次不发起应用市场跳转

### 分享 App

- 展示为可点击操作项
- 文案中明确未来支持微信 / QQ 分享
- 点击后仅显示占位提示，例如“微信 / QQ 分享功能暂未开放”
- 本次不发起系统分享或第三方分享逻辑

## 代码结构

### SupportFeedbackFragment

新增 `SupportFeedbackFragment`，职责限定为：

- 绑定页面文案
- 处理返回按钮
- 处理邮箱复制
- 处理评分与分享的占位点击反馈

该页面不负责持久化、不请求网络、不依赖额外状态层。

### 布局文件

新增 `fragment_support_feedback.xml`，复用当前设置模块二级页的视觉语言，采用静态内容布局即可。

建议结构：

- 根布局延续设置页背景
- 顶部返回按钮
- 标题与说明卡片
- 3 个可点击条目卡片

### 设置容器路由

调整 `SettingsContainerFragment` 中的分发逻辑：

- `TUNER -> SettingsFragment`
- `METRONOME -> MetronomeSettingsFragment`
- `GENERAL -> GeneralSettingsFragment`
- `SUPPORT -> SupportFeedbackFragment`
- `ABOUT -> SettingsPlaceholderFragment`

本次只替换 `SUPPORT` 的目标页面，不修改其他设置分区的行为。

### 文案资源

在 `strings.xml` 中新增支持与反馈页所需文案，避免将文本硬编码在 `Fragment` 中。至少包括：

- 页面标题
- 页面副标题
- 联系邮箱标题
- 联系邮箱说明
- 应用评分标题
- 应用评分说明
- 分享 App 标题
- 分享 App 说明
- 复制成功提示
- 复制失败提示
- 评分占位提示
- 分享占位提示

## 异常与边界处理

### 剪贴板异常

如果系统剪贴板服务获取失败或复制过程异常：

- 页面不得崩溃
- 通过短提示反馈失败，例如“复制失败，请稍后重试”

### 占位功能边界

由于“应用评分”和“分享 App”本次明确不接真实能力，因此：

- 不创建市场跳转 `Intent`
- 不创建分享 `Intent`
- 不校验应用市场或第三方 App 是否安装
- 不增加任何外部依赖

### 页面重建

页面内容为静态结构，无需额外状态恢复策略。发生配置变更或页面重建时，只要界面和点击行为仍可正常使用即可。

## 测试策略

### 仪器测试

至少覆盖以下路径：

1. 从设置首页点击“支持与反馈”后进入真实页面
2. 新页面能看到邮箱项、评分项和分享项
3. 点击返回按钮后回到设置首页
4. “关于”仍进入原占位页，证明路由未被误改

### 手工验证

至少覆盖以下场景：

1. 点击邮箱后文本已进入剪贴板，且出现复制成功提示
2. 剪贴板服务异常时页面不崩溃，并出现失败提示
3. 点击“应用评分”只出现占位提示，不发生跳转
4. 点击“分享 App”只出现占位提示，不发生跳转
5. 返回按钮可以稳定返回设置首页

## 明确不做

本次设计明确不包含以下内容：

- 改动“关于”页面
- 实现真实应用市场详情页跳转
- 实现微信 / QQ 或系统分享能力
- 引入 `SupportFeedbackViewModel`
- 增加持久化、远程配置或埋点逻辑
- 改造设置首页整体布局
- 调整底部导航结构

## 实现摘要

本次设计以最小改动方式将“支持与反馈”升级为真实设置二级页，仅把邮箱复制做成真实可用能力，评分与分享保留为明确可见的占位操作。这样既能完成当前设置页展示需求，也能为后续接入应用市场评分与微信 / QQ 分享保留清晰扩展点，同时不影响现有“关于”占位页和其他设置分区。
