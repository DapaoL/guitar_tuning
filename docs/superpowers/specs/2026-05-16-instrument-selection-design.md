# 乐器选择设计

**日期：** 2026-05-16

**目标：** 在首页调音页新增乐器选择能力，支持 `吉他`、`贝斯`、`尤克里里` 三种乐器。用户切换乐器后，当前页要立即切换对应的标准调弦目标、弦数展示、参考音播放和自动识别候选集合。本次只支持标准调弦，同时在代码结构上为后续特殊调弦预留扩展点，但不新增任何特殊调弦入口 UI。

## 背景

当前调音能力主要集中在 `HomeFragment`，并且实现默认围绕 6 弦吉他的标准调弦展开：

- 弦数据通过 `GuitarTone.standardStrings(referenceA4Hz)` 和 `standardStringAt(...)` 获取
- 手动选弦、自动识别选弦、参考音播放都依赖吉他的标准弦集合
- 首页布局中已经存在乐器选择点击入口，并且 `HomeFragment.instrumentSelection(view: View)` 已预留空方法
- 项目资源目录中已经包含贝斯和尤克里里的图片资源：
  - `app/src/main/res/drawable-xxhdpi/bass_ic.png`
  - `app/src/main/res/drawable-xxhdpi/ukulele_ic.png`

这意味着本次功能的核心不是新增入口，而是把首页调音逻辑从“只支持吉他”提升为“支持多乐器标准调弦”，同时保持当前页面结构和调音计算流程尽量稳定。

## 已确认范围

以下内容已经确认：

- 本次支持三种乐器：`吉他`、`贝斯`、`尤克里里`
- 每种乐器当前只支持 `标准调弦`
- 特殊调弦本次只做代码结构预留，不显示入口，不做占位页，不做空交互
- 切换乐器后，当前已选弦会重置到该乐器的默认弦
- 本次不要求把当前乐器持久化到本地；重新进入应用后可回到默认乐器

## 推荐方案

采用“统一调音页 + 乐器配置模型”的方案：

- 在现有调音设置和调音页面之上增加一层独立的乐器模型
- 将“标准弦集合、默认弦、展示名称、图片资源”统一收敛到乐器配置中
- `HomeFragment` 和 `HomeViewModel` 改为依赖“当前乐器配置”而不是写死的吉他工具方法
- 在配置模型中预留未来扩展到多调弦预设的结构

不推荐直接在 `HomeFragment` 中增加大量 `if/else` 分支来分别处理三种乐器，因为这会让未来增加特殊调弦时的维护成本迅速上升。

也不推荐为每种乐器拆分独立页面，因为当前功能只是在同一套调音界面下更换目标弦集合和视觉资源，拆页会带来不必要的重复实现。

## 用户可见行为

### 乐器切换入口

首页保留现有乐器选择入口和现有 UI 方案。用户点击后，进入您已经完成的乐器选择交互流程。

本次设计不重新定义入口样式，只规定入口触发后的业务行为。

### 乐器切换结果

用户选择目标乐器后，首页需要立即同步以下状态：

- 顶部乐器名称更新为当前乐器
- 乐器主视觉图片切换为当前乐器对应资源
- 弦按钮数量和标签切换为当前乐器的标准调弦集合
- 当前选中弦重置为该乐器的默认弦
- 参考音播放改为播放当前选中弦的目标频率
- 自动识别时，只在当前乐器的标准弦集合中匹配最近目标弦

### 标准调弦定义

本次每种乐器只注册一个标准调弦预设：

- 吉他：`E A D G B E`
- 贝斯：`E A D G`
- 尤克里里：`G C E A`

为了和现有页面的“从高音弦到低音弦/从低音弦到高音弦”显示习惯保持一致，最终 UI 中每根弦的显示顺序应沿用当前页面约定，但配置模型内部必须能明确表达每根弦的音名、序号和目标频率。

## 数据模型设计

### 乐器类型

建议新增独立枚举，例如：

```kotlin
enum class InstrumentType {
    GUITAR,
    BASS,
    UKULELE
}
```

这个枚举代表当前选中的乐器类型，是页面状态和未来调弦扩展的第一层维度。

### 乐器配置

建议新增统一的乐器配置模型，至少包含以下信息：

- `instrumentType`
- `displayName`
- `imageRes`
- `standardTuningId`
- `tunings`
- `defaultStringIndex`

其中：

- `tunings` 当前虽然只会包含一个 `standard` 预设，但必须设计为集合或可扩展结构
- `defaultStringIndex` 用于乐器切换后的默认弦重置
- `imageRes` 用于首页主视觉切换

### 调弦预设

建议新增独立的调弦预设模型，例如：

- 预设 ID，例如 `standard`
- 预设展示名
- 目标弦列表

目标弦列表中的单个元素需要能够表达：

- 弦序号
- 音名标签
- 基于当前 A4 参考频率推导出的目标频率

本次只使用 `standard`，但结构上必须允许以后为同一种乐器追加更多预设，例如：

- 吉他的 `drop_d`
- 尤克里里的 `low_g`

## 与现有工具类的关系

当前 `GuitarTone` 的职责是“围绕吉他标准弦提供工具方法”。本次设计需要把这层能力提升为“根据当前乐器和调弦预设返回目标弦集合”的统一入口。

推荐改造方向：

- 保留已有频率计算逻辑和 `referenceA4Hz` 参与方式
- 把仅针对吉他的工具方法抽象成更通用的乐器弦集合生成能力
- `HomeFragment` 不再直接假设“永远有 6 根吉他弦”

无论最终是扩展现有 `GuitarTone`，还是引入新的 `InstrumentTone` / `TuningPreset` 工具层，边界都应保持一致：页面只拿“当前乐器可用的目标弦集合”，不在 Fragment 中手写各乐器频率表。

## 页面状态设计

### HomeViewModel

`HomeViewModel` 需要新增“当前乐器”状态，并负责提供以下基础能力：

- 获取当前乐器配置
- 切换当前乐器
- 在乐器切换后同步默认弦索引
- 向页面暴露当前乐器名称和目标弦集合

由于本次不要求本地持久化，当前乐器状态可以仅保存在 `HomeViewModel` 生命周期内。

### HomeFragment

`HomeFragment.instrumentSelection(view: View)` 负责承接您已经做好的乐器选择 UI，并在用户确认选择后调用 ViewModel 的乐器切换逻辑。

切换成功后，`HomeFragment` 需要刷新：

- 乐器标题文案
- 主视觉图片
- 弦按钮显示/隐藏与标签
- 当前选中弦展示
- 当前页面用于调音判断和参考音播放的目标弦集合

### 默认弦重置规则

切换乐器后不做“位置映射”或“保留上一乐器选弦”的策略，而是直接重置到新乐器默认弦：

- 吉他：默认弦由配置定义
- 贝斯：默认弦由配置定义
- 尤克里里：默认弦由配置定义

如果当前选中弦索引因为乐器变化而越界，也必须回退到该乐器默认弦。

## 调音流程变更

### 手动选弦

手动选弦逻辑不再默认使用吉他 6 弦数据，而是从当前乐器的当前调弦预设中读取目标弦。

页面上的弦按钮数量可以保留现有 6 个视图节点，但必须保证：

- 4 弦乐器下，多余的弦按钮被正确隐藏或禁用
- 可见弦按钮的标签、序号和点击映射都与当前乐器配置一致
- 参考音播放只针对当前乐器存在的弦工作

### 自动识别

自动识别时，候选目标弦集合必须切换为当前乐器的标准调弦集合。

也就是说：

- 吉他时，在 6 根吉他弦中找最近目标
- 贝斯时，只在 4 根贝斯弦中找最近目标
- 尤克里里时，只在 4 根尤克里里弦中找最近目标

自动识别开关状态本身不因为乐器切换而变化。

### 参考音播放

参考音播放沿用当前音频播放机制，但目标频率来自“当前乐器当前选中弦”的频率，而不是固定的吉他标准弦。

### A4 参考频率兼容

当前调音页已经支持通过 `TunerSettings.referenceA4Hz` 调整参考频率。

本次乐器选择设计必须继续兼容这套能力：

- 所有乐器的目标弦频率都基于当前 `referenceA4Hz` 重新计算
- 切换乐器不能绕开现有 A4 设置
- 后续新增特殊调弦时也必须沿用同一套参考频率逻辑

## 资源与展示

### 图片资源

首页主视觉需要根据乐器切换以下图片资源：

- 吉他：沿用当前吉他图片资源
- 贝斯：`bass_ic.png`
- 尤克里里：`ukulele_ic.png`

如果某个目标资源异常缺失，页面应回退到默认吉他图片，避免页面崩溃或出现空白主视觉。

### 文案

建议补充或复用以下文案资源：

- 乐器名称：吉他、贝斯、尤克里里
- 标准调弦预留文案：当前版本无需展示入口，因此不需要新增“特殊调弦”按钮文案

本次如果页面上存在已做好的乐器选择 UI 文案，应以现有 UI 为准，文档只约束业务含义。

## 特殊调弦预留策略

本次不做任何用户可见入口，但代码结构必须具备扩展能力。

最低要求：

- 乐器配置中不要把“标准调弦”写死成单一字段，应该保留“调弦预设集合”概念
- 当前页面状态不要只记录“当前乐器”，最好能自然扩展为“当前乐器 + 当前调弦预设”
- 现有逻辑中的“获取目标弦集合”入口应从一开始就按“乐器 + 调弦预设”设计

这样后续新增特殊调弦时，只需要补充数据和入口交互，而不必推翻首页调音核心逻辑。

## 错误处理与边界

- 如果乐器切换结果为空或不合法，保持当前乐器不变
- 如果目标弦集合为空，页面回退到默认吉他标准调弦，避免调音页进入不可用状态
- 如果当前选中弦索引越界，回退到当前乐器默认弦
- 如果自动识别没有找到合适目标弦，保持当前显示，不强制切换
- 如果图片资源加载失败，回退到默认吉他图

本次不需要为这些恢复行为增加额外弹窗或错误提示，以保证交互简单稳定。

## 测试策略

### 单元测试

至少覆盖以下内容：

1. 三种乐器的标准调弦配置是否正确
2. 切换乐器后默认弦索引是否正确重置
3. 当前乐器对应的目标弦集合是否正确返回
4. 4 弦乐器下不会返回多余的弦配置
5. A4 参考频率变化时，目标弦频率是否仍然正确生成

### 手工验证

至少覆盖以下内容：

1. 首页选择吉他、贝斯、尤克里里后，标题和图片正确切换
2. 贝斯和尤克里里只显示 4 根弦，且点击映射正确
3. 切换乐器后，当前选中弦会重置到默认弦
4. 手动点弦后的参考音播放与当前乐器目标弦一致
5. 自动识别不会继续按吉他 6 弦去匹配贝斯或尤克里里
6. 修改 A4 参考频率后，三种乐器都继续使用新的参考频率

## 明确不做

本次设计明确不包含以下内容：

- 当前乐器的本地持久化保存
- 特殊调弦入口 UI
- 特殊调弦占位页
- 特殊调弦具体预设实现
- 为不同乐器拆分独立 Fragment
- 重写现有调音算法或音频采集链路

## 实现摘要

本次功能将在现有首页调音页中引入一层独立的乐器配置模型，使调音目标从“固定吉他标准弦”升级为“按当前乐器返回标准调弦集合”。首页继续复用现有布局和调音流程，但在乐器切换后立即刷新主视觉、弦按钮、默认选弦、参考音和自动识别候选集合。同时，数据结构从一开始就为未来的特殊调弦保留扩展位，确保后续新增更多调弦时不需要重新拆解首页核心逻辑。
